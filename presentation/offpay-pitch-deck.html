Step-by-Step Protocol

Step 1 (Receiver) — Enter amount → CSPRNG 16-byte nonce → display OFFPAY_REQUEST QR
Step 2 (Sender) — Scan QR → select bonds → SHA-256 digest → Ed25519_Sign with hardware-protected private key → mark bonds spent in SQLite → display OFFPAY_PAYMENT QR
Step 3 (Receiver) — Verify server signature (bond authenticity) + sender signature (transaction integrity) → validate nonce + amount → commit as pending_sync

3 Connectivity Modes (State Machine)

⚡ Mode 1 — Fully Offline (Core)

RFID tap → LittleFS RAM cache deduction → LCD display → buzzer audio cue. Zero power, zero connectivity. Works on a mountain at 5,000m.

🌐 Mode 2 — Local Wi-Fi REST API (LAN)

Embedded HTTP server on port 80. Web UI (bondpay-ui.html): live dashboard, card management, payment trigger, CSV export — no cloud needed.

☁️ Mode 3 — Cloud MQTT Sync (Global)

Broadcasts live transaction events globally via MQTT. Multi-device pairing by QR scan. Cashier phone + customer screen + ESP32 hardware all in real-time sync.

3-Tier Anti-Double-Spend Defense

🔒
Tier 1 — Immediate Local SQLite Lock Bond marked status='spent' in SQLite before the Payment QR is rendered. The sender's own device prevents reuse at source.
🏛️
Tier 2 — Server Unique Constraint First receiver to sync wins. bond_redemptions table has a UNIQUE constraint on Bond ID. Duplicate redemptions are mathematically rejected.
🪪
Tier 3 — KYC Identity Accountability Every fraudulent transaction carries the attacker's own Ed25519 signature + KYC-verified User ID. Server flags fraud_flags, suspends account immediately.

Threat Matrix

🎭
Counterfeit Bonds Server Ed25519 watermark verified offline by receiver — forged bonds are mathematically impossible to pass.
🔁
Replay Attacks (QR re-scan) CSPRNG nonces + timestamps stored in local SQLite — duplicate nonce rejection prevents any QR from being re-used.
📲
APK / App Tampering Receiver verifies signatures independently — bypassing the sender's local checks provides zero benefit.
🦠
Private Key Theft Ed25519 private keys in Android Keystore / iOS Keychain hardware enclave. They never leave the chip — even malware cannot extract them.

Q: How is double-spending prevented?
3-Tier: ① SQLite marks bond spent before QR renders. ② Server bond_redemptions UNIQUE constraint — first sync wins. ③ KYC identity + crypto sig → fraud_flags suspension.
Q: Why QR and not Bluetooth / NFC?
100% of phones have a camera. NFC absent from budget Androids in Nepal. Bluetooth requires pairing — 30s latency + permissions. QR: universal, instant, works in sunlight, zero setup.
Q: How do you handle change (NPR 350 with NPR 500)?
Bonds are issued in small denominations: NPR 100, 200, 500. Sender selects exact combinations. Receiver can issue a reverse offline voucher for the difference.
